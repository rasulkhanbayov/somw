Why each step is there

② needs no physics equations, only the simulator. ③ caps how many bad motions get through. ⑤ supplies the internal stress that generated frames lack. ④–⑥ simulate only what failed.

Cost per query: generate 0.05× + one check ≈ 0.03× of a full simulation; steps ④–⑥ run only for rejected motions.

How to walk through it. The query is a 3D object (2,048 points), its material (stiffness E, Poisson ratio) and a push (where, which direction, how strong), sometimes gravity and a floor. ① PhysCtrl’s frozen diffusion model predicts the 24-frame motion in a quarter of a second. ② We read positions and velocities off the generated frames and restart the physics simulator from there for 4 frames, on a cheap 64-cubed grid. If the generated motion obeyed physics, the simulator would follow it; the drift between them is the score. For one object we use one window at the strongest event in the motion; for two objects, three windows. ③ The threshold (0.026) was calibrated on separate objects, so it comes with a guarantee: at most about 10% of bad motions pass. ④ If it fails, we walk check windows at frames 0, 3, 7, 11, 15, 19 and find the first failure, frame k; the frames before k passed and are kept. ⑤ Generated frames do not carry the object’s internal stress, so we run a cheap simulation from the true starting state up to k, which does. ⑥ From that state we re-simulate only frames k to 24 at a tuned setting (96-cubed grid). For two objects, the cheap simulation watches the gap between them and hands over to an accurate setting (125-cubed grid) one frame before they come within 3 grid cells. If the very first check fails, we simulate the whole clip. ⑦ PhysCtrl’s own tracking and video model render the final motion, unchanged.
